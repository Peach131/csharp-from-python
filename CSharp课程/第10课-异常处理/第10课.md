## 一、先看"没有异常处理"会怎样

```csharp
Console.Write("请输入一个数字：");
string input = Console.ReadLine()!;
int n = int.Parse(input);              // ← 如果输入 "abc"？
Console.WriteLine($"你输入的是 {n}");
```

**输入 `abc` 时，程序直接崩溃**：

```
Unhandled exception. System.FormatException: The input string 'abc' was not in a correct format.
   at System.Number.ThrowOverflowOrFormatException(...)
   at System.Int32.Parse(String s)
   ...
```

**注意最后那几行** —— 那是**调用堆栈**，告诉你"错误发生在哪个方法的哪一行"，一路往上追。

**这个错误信息其实很有用**，但**用户看到会很懵，而且程序死了**。

## 二、`try` / `catch` —— 捕获异常

```csharp
try
{
    // 可能出错的代码放这里
    Console.Write("请输入一个数字：");
    string input = Console.ReadLine()!;
    int n = int.Parse(input);
    Console.WriteLine($"你输入的是 {n}");
}
catch (FormatException ex)
{
    // 出错时执行这里
    Console.WriteLine($"输入格式不对：{ex.Message}");
}
```

**三段结构**：

```
try
{
    // 尝试执行 —— 出异常就【立刻跳到】对应的 catch
}
catch (异常类型 变量名)
{
    // 处理异常 —— ex 里有错误信息
}
```

**关键理解**：

> **`try` 块里一旦发生异常，后面的代码【不再执行】，直接跳到 `catch`。**

```csharp
try
{
    Console.WriteLine("A");
    int x = int.Parse("abc");       // ← 这里抛异常
    Console.WriteLine("B");         // ← 不会执行
}
catch (FormatException)
{
    Console.WriteLine("C");         // ← 直接跳到这里
}
// 输出：A C
```

> **Python 对照**：**语法几乎一模一样**，只是关键字拼写和符号不同。
> ```python
> try:
>     x = int("abc")
> except ValueError as e:
>     print(f"错误：{e}")
> ```
> ```csharp
> try
> {
>     int x = int.Parse("abc");
> }
> catch (FormatException ex)
> {
>     Console.WriteLine($"错误：{ex.Message}");
> }
> ```
> **区别**：Python 用缩进，C# 用 `{ }`；Python 的异常类型名和 C# 不同。

## 三、多种异常，分别处理

```csharp
try
{
    Console.Write("请输入被除数：");
    int a = int.Parse(Console.ReadLine()!);

    Console.Write("请输入除数：");
    int b = int.Parse(Console.ReadLine()!);

    Console.WriteLine($"结果：{a / b}");
}
catch (FormatException ex)                 // 输入不是数字
{
    Console.WriteLine($"格式错误：{ex.Message}");
}
catch (DivideByZeroException)              // 除数是 0
{
    Console.WriteLine("除数不能为零！");
}
catch (OverflowException)                  // 数字超出 int 范围
{
    Console.WriteLine("数字太大了");
}
```

**`catch` 的顺序很重要**：

```csharp
try { ... }
catch (Exception ex) { }            // ← 如果这个写在最前面……
catch (FormatException ex) { }      // ← 这个永远不会被执行（编译警告/错误）
```

> **规则：从"最具体"到"最宽泛"排列。**
> `Exception` 是所有异常的父类（第 07 课的继承！），写在最前面会把后面全挡住。

### `catch` 的几种写法

```csharp
catch (FormatException ex) { }       // 捕获特定类型，用 ex
catch (FormatException) { }          // 捕获但不用 ex（不需要详细信息时）
catch { }                            // ⚠️ 捕获所有异常 —— 危险！见第六节
```

## 四、`finally` —— 无论如何都执行

```csharp
try
{
    Console.WriteLine("1. try 开始");
    throw new Exception("出错了");
}
catch (Exception ex)
{
    Console.WriteLine($"2. 捕获到：{ex.Message}");
}
finally
{
    Console.WriteLine("3. finally —— 无论有没有异常都会执行");
}
```

**`finally` 的三种执行时机**：

| 情况 | `finally` 会执行吗 |
|---|---|
| `try` 正常结束 | ✅ 会 |
| `try` 里抛了异常，被 `catch` 了 | ✅ 会 |
| `try` 里抛了异常，没被 `catch`（程序要崩了） | ✅ **仍然会** |
| `try` 里 `return` 了 | ✅ **仍然会** |

**用途**：**清理工作**（关闭文件、断开连接、释放资源）。

```csharp
FileStream? file = null;
try
{
    file = File.OpenRead("data.txt");
    // 读文件...
}
catch (FileNotFoundException)
{
    Console.WriteLine("文件不存在");
}
finally
{
    file?.Close();          // ★ 无论成功失败，都要关文件
}
```

> **Python 对照**：Python 也有 `finally`，用法完全一样。
> 但 C# 里更常用 **`using` 语句**来自动释放资源（第 13 课会讲）：
> ```csharp
> using var file = File.OpenRead("data.txt");   // 出了作用域自动关闭
> ```

## 五、`throw` —— 抛出异常

### 抛出内置异常

```csharp
static int Divide(int a, int b)
{
    if (b == 0)
    {
        throw new DivideByZeroException("除数不能为 0");
    }
    return a / b;
}
```

**`throw new 异常类型(消息)` 的语法**：

```
throw  new  DivideByZeroException  ( "消息" ) ;
  │     │          │                  │
  │     │          └── 异常类型        └── 描述信息（可选）
  │     └── 创建一个异常【对象】（第 05 课的 new！）
  └── 抛出它
```

### ⚠️ 重新抛出：`throw;` 不要写 `throw ex;`

```csharp
try
{
    RiskyMethod();
}
catch (Exception ex)
{
    _logger.LogError(ex, "出错了");

    throw;              // ✅ 保留完整的调用堆栈
    // throw ex;        // ❌ 会【重置】堆栈，丢失原始出错位置！
}
```

**这是个非常隐蔽的坑**：
- `throw;` —— 原样抛出去，堆栈完整
- `throw ex;` —— 抛出去但**堆栈从这一行重新开始**，你再也查不到原始错误发生在哪

> **记住：重新抛出永远用 `throw;`（不带变量）。**

### 异常筛选器 `when`

```csharp
try
{
    ProcessOrder(orderId, amount);
}
catch (InvalidOperationException ex) when (ex.Message.Contains("库存"))
{
    Console.WriteLine("库存不足，稍后重试");
}
catch (InvalidOperationException ex) when (ex.Message.Contains("余额"))
{
    Console.WriteLine("余额不足，请充值");
}
```

**`when` 让你"只在满足条件时才捕获"**，不满足就继续往上抛。

## 六、⚠️ 最重要的原则：不要"吞异常"

**这是初学者最容易犯、后果最严重的错误**：

```csharp
try
{
    DoSomethingImportant();
}
catch (Exception)
{
    // 什么都不做 ← ★★★ 这就是"吞异常"
}
```

**为什么危险？**

程序出了问题，但：
- ❌ 没有报错信息
- ❌ 没有日志
- ❌ 用户看到的是"功能没生效"，但不知道为什么
- ❌ 你排查时**完全不知道发生了什么**

**这比程序直接崩溃还糟糕** —— 崩溃至少告诉你"这里有 bug"，吞异常会让你**以为一切正常**。

### 三种写法对比

```csharp
// ❌ 最差：完全吞掉
catch (Exception) { }

// ⚠️ 差：吞掉了，但至少知道出错了
catch (Exception ex)
{
    Console.WriteLine("出错了");         // 信息太少，不知道怎么修
}

// ✅ 好：记录 + 决定怎么处理
catch (Exception ex)
{
    Console.WriteLine($"处理订单失败：{ex.Message}");
    // 真实项目里还应该写日志：
    // _logger.LogError(ex, "处理订单 {OrderId} 失败", orderId);
    throw;                              // 或者自己处理掉，但要说明理由
}
```

### 判断"这个异常我要不要捕获"

问自己三句话：

| 问题 | 如果答案是"否" |
|---|---|
| **我能处理它吗？**（有备用方案） | 不要捕获，让它往上抛 |
| **我能补充什么信息？**（上下文、日志） | 不要捕获 |
| **吞掉它安全吗？**（不影响后续逻辑） | **千万不要吞** |

> **实用建议**：**宁可不捕获，也不要空捕获。**
> 让异常往上抛，至少程序会明确失败；吞掉它，程序会"安静地做错事"。

## 七、常见异常类型

| 异常 | 什么时候抛 |
|---|---|
| `FormatException` | `int.Parse("abc")` —— 格式不对 |
| `OverflowException` | 数字超出类型范围 |
| `DivideByZeroException` | 整数除以 0 |
| `NullReferenceException` | 对 `null` 调用成员（**最常见的异常**） |
| `IndexOutOfRangeException` | 数组索引越界 |
| `KeyNotFoundException` | 字典的键不存在 |
| `InvalidOperationException` | 对象状态不允许这个操作 |
| `ArgumentException` | 传了不合法的参数 |
| `ArgumentNullException` | 传了 `null` 参数 |
| `FileNotFoundException` | 文件不存在 |
| `NotImplementedException` | 方法还没实现（占位用） |

### `NullReferenceException` 值得单独说

**它是最常见的异常**，也是**最难查的**——因为异常信息只告诉你"某处为 null"，不告诉你是谁把它变成 null 的。

```csharp
string? name = null;
Console.WriteLine(name.Length);        // ❌ NullReferenceException
```

**第 01 课讲过 `string` 字段默认是 `null`**，忘了初始化就会撞上这个。

**防御方法**：

```csharp
// 方法 1：判空
if (name is not null)
{
    Console.WriteLine(name.Length);
}

// 方法 2：空条件运算符 ?.
Console.WriteLine(name?.Length);        // name 是 null 就返回 null，不崩

// 方法 3：空合并运算符 ??
string display = name ?? "（未填写）";   // name 是 null 就用默认值

// 方法 4：空合并赋值 ??=
name ??= "默认名字";                    // 只有为 null 时才赋值
```

> **下一批课程（第 11-14 课）会专门讲"可空引用类型"**，
> 编译器能提前警告你"这里可能是 null"，很多 `NullReferenceException` 在编译期就能避免。

## 八、自定义异常

**当内置异常类型不够表达你的业务错误时**，可以自己定义：

```csharp
// 惯例：类名以 Exception 结尾，继承 Exception
class InsufficientBalanceException : Exception
{
    public decimal Balance { get; }        // 可以带额外信息
    public decimal Required { get; }

    public InsufficientBalanceException(decimal balance, decimal required)
        : base($"余额不足：需要 {required:F2}，实际只有 {balance:F2}")
    {
        Balance = balance;
        Required = required;
    }
}
```

**使用**：

```csharp
static void Withdraw(decimal balance, decimal amount)
{
    if (amount > balance)
    {
        throw new InsufficientBalanceException(balance, amount);
    }
    Console.WriteLine("取款成功");
}

try
{
    Withdraw(100, 500);
}
catch (InsufficientBalanceException ex)
{
    Console.WriteLine(ex.Message);
    Console.WriteLine($"我的余额是 {ex.Balance}，想取 {ex.Required}");
}
```

**为什么要自定义异常？**
- **调用方可以精确捕获它**（不会和别的异常混在一起）
- **可以携带额外数据**（`Balance`、`Required`）
- **业务语义清晰**

> **Python 对照**：完全一样的思路。
> ```python
> class InsufficientBalanceError(Exception):
>     def __init__(self, balance, required):
>         super().__init__(f"余额不足：需要 {required}，实际 {balance}")
> ```

## 九、⚠️ 不要用异常做流程控制

**异常是有性能代价的**（要捕获调用堆栈），所以不要用它来处理"正常的业务分支"。

```csharp
// ❌ 用异常做流程控制
try
{
    int n = int.Parse(input);          // 期待它抛异常来判断输入是否合法
    Console.WriteLine("是数字");
}
catch (FormatException)
{
    Console.WriteLine("不是数字");
}

// ✅ 用 Try 系列方法（第 01 课学过）
if (int.TryParse(input, out int n))
{
    Console.WriteLine("是数字");
}
else
{
    Console.WriteLine("不是数字");
}
```

**判断标准**：

| 情况 | 用什么 |
|---|---|
| **可预期的、正常的**分支（用户输错、找不到数据） | `TryXxx` 方法 / 返回 bool |
| **意外的、异常的**情况（文件损坏、网络断开、违反契约） | **异常** |

> **一句话**：**"错误"和"异常"不是一回事。**
> 用户输入错误是**正常情况**（会有很多次），不该用异常；
> 磁盘突然满了才是**异常情况**。

## 十、本课新语法速查表

| 语法 | 作用 | Python 对照 | 易错点 |
|---|---|---|---|
| `try { } catch (T ex) { }` | 捕获异常 | `try: / except T as e:` | 用 `{ }` 不是缩进 |
| `catch (T) when (条件)` | 条件捕获 | `except T if 条件:` | — |
| `finally { }` | 一定执行 | `finally:` | 即使 `return` 也会执行 |
| `throw new T("msg")` | 抛异常 | `raise T("msg")` | — |
| `throw;` | 重新抛出（保留堆栈） | `raise` | **不要写 `throw ex;`** |
| `class XException : Exception` | 自定义异常 | `class XError(Exception)` | 惯例以 Exception 结尾 |
| `ex.Message` | 错误信息 | `str(e)` | — |
| `ex.StackTrace` | 调用堆栈 | `traceback` | — |
| `is null` / `?.` / `??` / `??=` | 防 null 系列 | `is None` / 无 | 防 `NullReferenceException` |
| `int.TryParse` | 不用异常的转换 | `try: int() except` | **推荐用它代替 try-catch** |
