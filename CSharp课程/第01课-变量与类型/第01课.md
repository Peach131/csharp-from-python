## 一、先理解：为什么 C# 必须写类型

Python 里你可以这样写：

```python
x = 5          # 不用写类型
x = "hello"    # 随时可以改成别的类型
```

C# 里必须这样写：

```csharp
int x = 5;         // 类型 名字 = 值;
// x = "hello";    // ❌ 编译错误！x 永远是 int，不能装字符串
```

**你第一次写 C# 会觉得"这不多此一举吗"。** 先看这个对比，你就明白为什么值得：

| | Python（动态类型） | C#（静态类型） |
|---|---|---|
| 声明变量 | `x = 5` | `int x = 5;` |
| 类型何时确定 | **运行时**（跑到那一行才知道） | **编译时**（写代码时就定了） |
| 类型写错了 | 跑到那一行才崩 | **打字的瞬间就标红** |
| IDE 能补全吗 | 猜（可能猜错） | **100% 准确** |
| 重命名变量安全吗 | 危险（字符串里的引用会漏） | `Shift+F6` 一次搞定 |

**核心权衡：**

> **Python 用"少打字"换"运行风险"。C# 用"多打字"换"编译期安全"。**

前两周你会觉得 C# 啰嗦，第 10 天左右你会开始享受它。**这不是心理安慰——因为报错提前暴露，真的能省下大量调试时间。**

## 二、变量声明的语法结构

```csharp
int age = 20;
│   │    │   │
│   │    │   └── 分号：语句结束，必须有
│   │    └────── 初始值：赋值给变量
│   └─────────── 变量名：你自己起，惯例小写开头
└─────────────── 类型：必须写！这是和 Python 最大的区别
```

**完整语法**：
```
类型 变量名 = 初始值;
```

### 变量命名规则（硬性规定）

| 规则 | 允许 | 不允许 |
|---|---|---|
| 只能用字母、数字、下划线 | `userName`、`user_name`、`name2` | `user-name`、`user name` |
| 不能以数字开头 | `name2` | `2name` |
| 不能是 C# 关键字 | `myClass` | `class`、`int`、`if` |
| 区分大小写 | `Name` 和 `name` 是**两个不同变量** | — |

### 命名惯例（不是硬规定，但不遵守会被同事骂）

```csharp
int age = 20;                // ✅ 局部变量：小驼峰 camelCase（首字母小写）
int userAge = 20;            // ✅ 多个单词：第二个单词起首字母大写
int user_age = 20;           // ❌ 下划线风格是 Python 的，C# 不用
int Age = 20;                // ⚠️ 能编译，但惯例不对（大写开头留给类名/属性）
```

> **Python 对照**：Python 用 `user_age`（蛇形命名），C# 用 `userAge`（驼峰命名）。
> **这个差异必须改过来**，否则代码一看就是"Python 味"。

## 三、7 种最常用的类型

### 整数类

| 类型 | 大小 | 范围 | 什么时候用 |
|---|---|---|---|
| `int` | 4 字节 | 约 ±21 亿 | **默认选择**，99% 的整数都用它 |
| `long` | 8 字节 | 约 ±9.2 × 10¹⁸ | 数字很大时（时间戳、大 ID） |
| `short` | 2 字节 | 约 ±3.2 万 | 很少用（省内存的场合） |
| `byte` | 1 字节 | 0 ~ 255 | 处理二进制数据 |

```csharp
int count = 100;
long timestamp = 1735689600L;    // 注意末尾的 L，表示这是 long 字面量
```

> ⚠️ **和 Python 的重大差异**：Python 的 `int` 是**任意精度**（能存 1 后面 1000 个 0）。
> C# 的 `int` 只有 32 位，**超出范围会溢出**，而且默认不报错！

```csharp
int max = int.MaxValue;          // 2147483647
Console.WriteLine(max + 1);      // -2147483648  ← 溢出变成负数了！
```

**这是 Python 程序员必踩的坑**。要存超大整数用 `long` 或 `System.Numerics.BigInteger`。

---

### 小数类 ⚠️ 这里有个大坑

| 类型 | 精度 | 什么时候用 |
|---|---|---|
| `double` | 15-16 位有效数字 | **科学计算、图形、物理**（默认的浮点类型） |
| `float` | 7 位有效数字 | 省内存的场合（Unity 里大量使用） |
| **`decimal`** | **28-29 位，且精确** | **金额、货币、财务计算** |

```csharp
double d = 0.1 + 0.2;
Console.WriteLine(d);              // 0.30000000000000004  ← 不是 0.3！

decimal m = 0.1m + 0.2m;           // 注意末尾的 m
Console.WriteLine(m);              // 0.3  ← 精确
```

**为什么？** `double` 是**二进制浮点**，`0.1` 在二进制里是无限循环小数，只能近似存储。
`decimal` 是**十进制浮点**，专门为"人能看懂的小数"设计的。

### ⚠️ 这不是理论问题——它会让你算错钱

**实测数据**（示例代码里的真实输出）：

| 场景 | `double` 的结果 | `decimal` 的结果 |
|---|---|---|
| 单价 `4.35` 元 × 100 件 | **434.99999999999994** ❌ | 435.00 ✅ |
| 单价 `19.99` 元 × 100 件 | **1998.9999999999998** ❌ | 1999.00 ✅ |
| 把 `0.1` 累加 10 次 | **0.9999999999999999** ❌ | 1.0 ✅ |

> **规则**：算钱**必须**用 `decimal`，绝不用 `double`。
> 这**不是风格问题——用 `double` 算账真的会算错**，而且误差会随交易次数累积。

---

### 布尔和字符

```csharp
bool isReady = true;         // 只有 true / false 两个值（小写！）
char grade = 'A';            // 单个字符，用【单引号】
```

> ⚠️ **`char` 用单引号 `'A'`，`string` 用双引号 `"A"`。** 混了会报错。
> Python 里没有单独的 `char` 类型，只有长度为 1 的字符串。

---

### 字符串

```csharp
string name = "qzl";                  // 用双引号
string empty = "";                    // 空字符串
string? maybeNull = null;             // 可能为 null（第 03 课详细讲）
```

**最常用的字符串操作**（先混个眼熟，不用背）：

```csharp
string s = "Hello World";

s.Length                // 11        长度（注意是属性，不是 len(s)）
s.ToUpper()             // "HELLO WORLD"
s.ToLower()             // "hello world"
s.Contains("World")     // true
s.Replace("World", "C#")// "Hello C#"
s.Trim()                // 去掉首尾空格
s.Split(' ')            // 按空格拆成数组
s.Substring(0, 5)       // "Hello"   取前 5 个字符
s[0]                    // 'H'       取第一个字符
```

> **Python 对照**：Python 是 `len(s)`（函数），C# 是 `s.Length`（属性）。
> Python 是 `s.upper()`，C# 是 `s.ToUpper()`（大写 T、大写 U）。

## 四、`var` —— 让编译器帮你推断类型

```csharp
var age = 20;              // 编译器推断出 age 是 int
var name = "qzl";          // 推断出 string
var price = 9.9m;          // 推断出 decimal
```

**⚠️ 关键理解：`var` 不是"动态类型"！**

```csharp
var x = 20;
// x = "hello";           // ❌ 编译错误！x 已经被推断为 int 了
```

`var` 只是让你**少打几个字**，类型在编译时**就已经确定并锁定**了。
它和 Python 的 `x = 20; x = "hello"` 完全是两回事。

**什么时候用 `var`？**

| 场景 | 建议 |
|---|---|
| 类型名很长（`Dictionary<string, List<int>>`） | ✅ 用 `var` |
| 一眼能看出类型（`var age = 20`） | ✅ 可以 |
| 看不出类型（`var result = GetData()`） | ❌ 写清楚类型，方便阅读 |
| **初学者阶段** | **建议先都写清楚类型**，加深印象 |

## 五、类型转换 —— 你以后天天要用

### 情况 1：从字符串转成数字（处理用户输入必用）

用户在控制台输入的是**字符串**，要算数必须转换。

```csharp
// ❌ 危险写法：输入不是数字就崩溃
string input = Console.ReadLine();
int num = int.Parse(input);        // 输入 "abc" → 抛异常，程序崩溃

// ✅ 安全写法：TryParse
string input2 = Console.ReadLine();
if (int.TryParse(input2, out int num2))
{
    Console.WriteLine($"转换成功，你输入的是 {num2}");
}
else
{
    Console.WriteLine("你输入的不是数字！");
}
```

**`TryParse` 的语法要拆开讲**（这里有个第 00 课没见过的关键字）：

```csharp
int.TryParse(input2, out int num2)
│              │        │    │
│              │        │    └── 变量名
│              │        └─────── 类型
│              └──────────────── out：表示"这个方法会给我一个值"
└─────────────────────────────── 要转换的字符串
```

**`out` 是什么？** 正常的返回值只能返回一个值。如果方法**既要告诉你"成功了没"（返回 bool），
又要给你"转换结果"（数字）**，就用 `out` 参数。

- 返回 `true`/`false` → 表示转换成功还是失败
- `out num2` → 装转换结果（**如果失败，`num2` 会是 0**）

> **Python 对照**：Python 用 `try: num = int(s) except ValueError:` 来处理。
> C# 的 `TryParse` 是另一种风格：**不抛异常，返回布尔值告诉你成功没**。
> **C# 里推荐用 `TryParse`**，因为异常很贵（第 10 课会讲为什么）。

### 情况 2：数字之间转换

```csharp
int a = 100;
long b = a;                 // ✅ 小范围 → 大范围：自动转换（隐式），安全
double c = a;               // ✅ int → double：自动转换

double d = 3.99;
// int e = d;               // ❌ 大范围 → 小范围：编译器不允许！
int e = (int)d;             // ✅ 必须显式转换，结果 3（直接砍掉小数，不是四舍五入）
int f = (int)Math.Round(d); // 要四舍五入就用 Math.Round，结果 4
```

**规律**：**能安全转换的自动来，可能丢数据的必须你明确写出来。**
这是 C# 在提醒你"这里可能出问题"。

### 情况 3：`Convert` 类

```csharp
string s = "123";
int x = Convert.ToInt32(s);      // 类似 int.Parse，但能处理 null（null 会变成 0）
```

**先用 `TryParse`，`Convert` 知道有这回事就行。**

## 六、常量：`const`

```csharp
const double Pi = 3.14159;       // 常量：一旦赋值，永远不能改
// Pi = 3;                       // ❌ 编译错误

double radius = 5;
double area = Pi * radius * radius;
```

**什么时候用 `const`？**
- 值永远不变，而且**在编译时就能确定**（比如圆周率、税率、最大重试次数）
- 好处：编译器会帮你检查"别改它"，而且有性能优化

> **Python 对照**：Python 没有真正的常量，只能靠"全大写命名"约定（`PI = 3.14`）表示"别改"。
> C# 里 `const` 是**编译器强制**的。

**命名惯例**：C# 的常量用 **PascalCase**（`MaxRetryCount`），不是 Python 的全大写（`MAX_RETRY_COUNT`）。

## 七、本课新语法速查表

| 语法 | 作用 | Python 对照 | 易错点 |
|---|---|---|---|
| `int x = 5;` | 声明整数变量 | `x = 5` | 必须写类型 + 分号 |
| `var x = 5;` | 让编译器推断类型 | — | **不是动态类型**，类型锁死了 |
| `double` | 双精度浮点 | `float` | 默认浮点类型 |
| `decimal` | 高精度十进制 | `decimal.Decimal` | **算钱必须用它**，字面量加 `m` |
| `long` | 64 位整数 | 无（Python int 无限精度） | 字面量加 `L` |
| `bool` | `true` / `false` | `True` / `False` | **小写！** |
| `char` | 单个字符 | 无 | 用**单引号** `'A'` |
| `string` | 字符串 | `str` | 用**双引号**，`s.Length` 不是 `len(s)` |
| `int.Parse(s)` | 字符串转整数 | `int(s)` | 失败会抛异常 |
| `int.TryParse(s, out int n)` | 安全转换 | 无直接对应 | 返回 bool，结果在 `out` 参数里 |
| `(int)d` | 强制转换 | `int(d)` | **直接砍掉小数**，不四舍五入 |
| `const` | 常量 | 无（靠约定） | 命名用 PascalCase |
| `$"{x:F2}"` | 格式化插值 | `f"{x:.2f}"` | 见下文 |

## 八、插值的格式化（`$"{值:格式}"`）

在 `{ }` 里加一个冒号和格式符，可以控制显示方式：

```csharp
double price = 12.5;

Console.WriteLine($"{price:F2}");      // 12.50      保留 2 位小数
Console.WriteLine($"{price:C}");       // ¥12.50     货币格式（跟随系统区域）
Console.WriteLine($"{price:P1}");      // 1,250.0%   百分比，1 位小数
Console.WriteLine($"{1234567:N0}");    // 1,234,567  千分位分隔
Console.WriteLine($"{42,10}|");        //         42| 右对齐，占 10 个字符宽
Console.WriteLine($"{42,-10}|");       // 42        | 左对齐
Console.WriteLine($"{3.14159:F3}");    // 3.142      3 位小数（会四舍五入）
```

> **Python 对照**：Python 是 `f"{price:.2f}"`，C# 是 `$"{price:F2}"`。
> 位置一样（冒号后面），但格式符不一样。
