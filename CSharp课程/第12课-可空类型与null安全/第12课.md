## 一、`NullReferenceException` —— 最常见也最难查的异常

```csharp
string name = null;              // 或者忘了赋值
Console.WriteLine(name.Length);  // ❌ NullReferenceException，程序崩溃
```

**为什么说它"最难查"？**
因为异常信息只告诉你 **"某处为 null"**，**不告诉你是谁把它变成 null 的**。

```csharp
// 三层调用，到底哪一层传了 null？
var order = GetOrder(id);           // ← 这里返回了 null？
ProcessOrder(order);                // ← 还是这里传错了？
```

**它也是最常见的异常** —— 在真实项目里，`NullReferenceException` 常年占据崩溃原因第一名。

## 二、第 01 课埋的伏笔：`T?` 对两种类型含义不同

第 01 课你见过这个，当时我说"第 12 课会专门讲"。现在讲。

### 值类型的 `?` → `Nullable<T>`

```csharp
int? a = null;                   // ✅ 可以用
int  b = null;                   // ❌ 编译错误：int 不能为 null
```

**为什么 `int` 不能为 `null`，但 `int?` 可以？**

因为 `int?` **不是 `int`**，它其实是 `Nullable<int>` —— 一个真正的 `struct`：

```csharp
public struct Nullable<T> where T : struct
{
    private bool hasValue;
    private T value;
    // ...
}
```

**所以 `int?` 里其实有两个东西**：一个 `bool`（有没有值）+ 一个 `int`（值）。

**这就是为什么 `int?` 有这两个成员**：

```csharp
int? x = 42;

Console.WriteLine(x.HasValue);   // True   ← 有没有值
Console.WriteLine(x.Value);      // 42     ← 真正的值

int? y = null;
Console.WriteLine(y.HasValue);   // False
// Console.WriteLine(y.Value);   // ❌ InvalidOperationException！对 null 取 Value 会抛异常
```

### 引用类型的 `?` → 只是一个"编译期标记"

```csharp
string s = "abc";       // 非空字符串
string? t = null;       // 可能为 null 的字符串
```

**关键区别**：

| | `int?` | `string?` |
|---|---|---|
| 底层是什么 | `Nullable<int>`（一个 struct） | **就是 `string`** |
| 有 `HasValue` 吗 | ✅ 有 | ❌ **没有** |
| 有 `Value` 吗 | ✅ 有 | ❌ 没有 |
| 运行时开销 | 有个包装 struct | **零开销**（`?` 只是给编译器看的） |
| 怎么判空 | `x.HasValue` 或 `x is null` | `x is null` |

> **这就是你在第 1 周踩过的那个坑**（`疑问与踩坑记录.md` #03）：
> 把 `SPoint` 从 `struct` 改成 `class` 之后，`SPoint?` 就**没有 `HasValue`** 了。
> **因为 `?` 的含义跟着类型变了。**

**记忆口诀**：
> **值类型的 `?` 是"包一层"，引用类型的 `?` 是"打个标记"。**

## 三、可空引用类型（NRT）—— 让编译器帮你抓 null

**这是 C# 8 引入的重大改进**，也是你现在项目里已经开启的功能
（`.csproj` 里的 `<Nullable>enable</Nullable>`）。

### 开启后的规则

```csharp
string  a = "abc";        // 声明为"非空"
string? b = null;         // 声明为"可能为空"

// a = null;              // ⚠️ 编译警告：不能把 null 赋给非空引用类型
Console.WriteLine(a.Length);      // ✅ 编译器放心

// Console.WriteLine(b.Length);   // ⚠️ 编译警告：b 可能是 null！
```

**注意是"警告"不是"错误"** —— 代码仍然能编译。但这个警告**极其有用**：

> **它把 `NullReferenceException` 从"运行时崩溃"提前到了"编译时提醒"。**

### 编译器怎么判断"这里安全吗"（null 状态分析）

```csharp
string? name = null;

// 编译器视角：name 的状态是 "maybe null"

if (name is not null)
{
    // 编译器视角：这里 name 的状态是 "not null"（它跟着 if 分支推理）
    Console.WriteLine(name.Length);      // ✅ 没有警告
}

Console.WriteLine(name.Length);          // ⚠️ 警告：这里 name 可能是 null
```

**编译器会顺着你的 `if` 判断推理** —— 这叫 **null 状态分析（null-state analysis）**。

### 三种消除警告的方式

```csharp
string? input = Console.ReadLine();

// ① 判空（推荐）
if (input is not null)
{
    Console.WriteLine(input.Length);
}

// ② 用 ?. 安全访问
Console.WriteLine(input?.Length);

// ③ 用 ?? 提供默认值
string safe = input ?? "";
Console.WriteLine(safe.Length);

// ④ 用 ! 告诉编译器"我保证它不是 null"（危险，慎用）
Console.WriteLine(input!.Length);        // ⚠️ 如果真是 null，一样会崩
```

> **`!`（null-forgiving operator，"原谅操作符"）的意思是"闭嘴，我知道我在干什么"。**
> **它不会做任何运行时检查**，只是让编译器别再警告。
> **滥用 `!` = 把编译器的保护关掉** —— 这是反模式。

## 四、三个必会的运算符

### `?.` 空条件运算符 —— "如果为 null 就不继续"

```csharp
string? name = null;

// 传统写法
int? len1 = name is null ? null : name.Length;

// ?. 写法（推荐）
int? len2 = name?.Length;                // name 为 null → 整个表达式是 null

// 链式调用
string? upper = name?.ToUpper()?.Trim(); // 任何一环是 null，整条链返回 null

// 对方法调用也适用
name?.ToUpper();                          // 不会崩
```

> **Python 对照**：Python 没有内置的 `?.`，要写 `name.upper() if name else None`。
> C# 的 `?.` 更简洁，而且可以链式用。

### `??` 空合并运算符 —— "为 null 就用默认值"

```csharp
string? input = null;

string display = input ?? "（未填写）";     // input 是 null → 用右边
Console.WriteLine(display);                 // （未填写）

string? hasValue = "abc";
Console.WriteLine(hasValue ?? "默认");      // abc（左边不是 null，用左边）
```

**可以链式**：

```csharp
string result = first ?? second ?? third ?? "兜底默认值";
// 从左到右，第一个非 null 的值
```

### `??=` 空合并赋值运算符 —— "为 null 才赋值"

```csharp
string? name = null;
name ??= "默认名字";        // name 是 null → 赋值
Console.WriteLine(name);    // 默认名字

name ??= "另一个名字";      // name 不是 null → 不赋值
Console.WriteLine(name);    // 默认名字（没变）
```

**典型用途**：延迟初始化缓存

```csharp
private List<string>? _cache;

public List<string> GetCache()
{
    _cache ??= new List<string>();      // 只在第一次时创建
    return _cache;
}
```

### 三者对照表

| 运算符 | 含义 | 例子 | 结果 |
|---|---|---|---|
| `?.` | 为 null 就**返回 null**，不继续 | `name?.Length` | `null` 或长度 |
| `??` | 为 null 就**用右边的值** | `name ?? "默认"` | `"默认"` |
| `??=` | 为 null 就**赋值** | `name ??= "默认"` | `name` 变成 `"默认"` |

## 五、`required` 和构造函数的 null 保护

### 问题：忘了初始化字段

```csharp
class Student
{
    public string Name { get; set; }      // ⚠️ CS8618 警告：构造函数退出时 Name 可能是 null
}

var s = new Student();
Console.WriteLine(s.Name.Length);          // 💥 崩了
```

**编译器会警告你**：

```
warning CS8618: 在退出构造函数时，不可为 null 的字段 "Name" 必须包含非 null 值
```

**这个警告是真 bug 的预言**，不是噪音。

### 三种解决方案

```csharp
// 方案 1：给默认值（最简单）
public string Name { get; set; } = "";

// 方案 2：构造函数里赋值
public string Name { get; }
public Student(string name) => Name = name;

// 方案 3：required（C# 11+，最推荐）
public required string Name { get; set; }
// 调用方必须写：new Student { Name = "张三" }
// 不写就是编译错误！
```

**`required` 的好处**：

```csharp
var s1 = new Student();                          // ❌ 编译错误：必须初始化 Name
var s2 = new Student { Name = "张三" };           // ✅
```

**编译器强制你在创建对象时就给它赋值** —— 从根上杜绝"忘了初始化"。

## 六、一个完整的实战例子

```csharp
class UserProfile
{
    public required string UserName { get; set; }
    public string? NickName { get; set; }         // 可选：可能没填
    public string? Email { get; set; }            // 可选
    public List<string>? Tags { get; set; }
}

static void ShowProfile(UserProfile user)
{
    // 必需的字段直接用（编译器保证不为 null）
    Console.WriteLine($"用户名：{user.UserName}");

    // 可选字段用 ?? 给默认值
    Console.WriteLine($"昵称：{user.NickName ?? "（未设置）"}");

    // 可选字段用 ?. 安全访问
    Console.WriteLine($"邮箱长度：{user.Email?.Length ?? 0}");

    // 集合用 ??= 延迟初始化
    user.Tags ??= new List<string>();
    Console.WriteLine($"标签数：{user.Tags.Count}");
}
```

**这段代码里没有任何 `if (x != null)` 的嵌套**，但完全不会崩 ——
因为**类型系统 + 运算符**已经把 null 处理好了。

## 七、本课新语法速查表

| 语法 | 作用 | Python 对照 | 易错点 |
|---|---|---|---|
| `int?` | 可空的值类型 | `Optional[int]` | 底层是 `Nullable<int>` |
| `x.HasValue` | 有没有值 | `x is not None` | **只有值类型有** |
| `x.Value` | 取出值 | `x` | 对 null 取 Value 会抛异常 |
| `string?` | 可能为 null 的引用 | `Optional[str]` | **运行时零开销** |
| `x?.Member` | 空条件访问 | `x.member if x else None` | 可链式 |
| `x ?? y` | 为 null 用 y | `x if x is not None else y` | 可链式 |
| `x ??= y` | 为 null 才赋值 | `if x is None: x = y` | — |
| `x!.Member` | 让编译器闭嘴 | 无 | **不做运行时检查，慎用** |
| `x is null` | 判空（推荐） | `x is None` | — |
| `is not null` | 判非空 | `x is not None` | — |
| `required` | 强制初始化 | `@dataclass` 必填字段 | C# 11+ |
| `??=` 初始化缓存 | 延迟初始化 | — | 常用模式 |
