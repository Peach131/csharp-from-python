## 一、为什么需要继承

假设要写三种动物：狗、猫、鸟。它们都有**名字**和**年龄**，都会**吃**：

```csharp
class Dog
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
    public void Eat() => Console.WriteLine($"{Name} 在吃东西");
    public void Bark() => Console.WriteLine($"{Name} 在汪汪叫");
}

class Cat
{
    public string Name { get; set; } = "";        // ← 重复
    public int Age { get; set; }                   // ← 重复
    public void Eat() => Console.WriteLine($"{Name} 在吃东西");   // ← 重复
    public void Meow() => Console.WriteLine($"{Name} 在喵喵叫");
}

class Bird
{
    public string Name { get; set; } = "";        // ← 又重复
    public int Age { get; set; }                   // ← 又重复
    public void Eat() => Console.WriteLine($"{Name} 在吃东西");   // ← 又重复
    public void Fly() => Console.WriteLine($"{Name} 在飞");
}
```

**问题**：`Name`、`Age`、`Eat` 被复制了三遍。想改 `Eat` 的行为要改三个地方。

### 用继承解决

**把共同的部分提取到一个"父类"里：**

```csharp
// 父类（基类）：放所有动物共有的东西
class Animal
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
    public void Eat() => Console.WriteLine($"{Name} 在吃东西");
}

// 子类（派生类）：自动拥有父类的一切，只需写自己特有的
class Dog : Animal              // ← 冒号表示"继承自 Animal"
{
    public void Bark() => Console.WriteLine($"{Name} 在汪汪叫");
}

class Cat : Animal
{
    public void Meow() => Console.WriteLine($"{Name} 在喵喵叫");
}
```

**用法**：

```csharp
var dog = new Dog { Name = "旺财", Age = 3 };
dog.Eat();          // ✅ 从父类继承来的
dog.Bark();         // ✅ 子类自己的
```

### 术语对照

| 说法 | 另一种说法 | 例子 |
|---|---|---|
| 父类 / 基类 | base class, superclass | `Animal` |
| 子类 / 派生类 | derived class, subclass | `Dog` |
| 继承 | inherit, extend | `class Dog : Animal` |

> **Python 对照**：完全一样的语法概念，只是符号不同。
> ```python
> class Animal: ...
> class Dog(Animal): ...     # Python 用括号
> ```
> ```csharp
> class Dog : Animal { }     // C# 用冒号
> ```

### ⚠️ 三个必须知道的限制

| 限制 | 说明 |
|---|---|
| **C# 不支持多重继承** | 一个类**只能有一个父类**：`class C : A, B` ❌（`B` 只能是接口） |
| 子类**继承 public 和 protected** | `private` 成员子类也访问不了 |
| 继承是**"是一个"** 关系 | `Dog` **是一个** `Animal` ✅；`Engine` 不是 `Car` 的一种 → 应该用组合 |

> **最后一条最重要**：**不要为了复用代码而乱用继承。**
> 判断标准：**"子类 是一个 父类" 说得通吗？**
> - ✅ `Dog 是一个 Animal` —— 说得通
> - ❌ `Car 是一个 Engine` —— 说不通，应该写成"Car **有一个** Engine"（组合）

## 二、`base` —— 访问父类

### 调用父类的构造函数

```csharp
class Animal
{
    public string Name { get; set; }

    // 父类的构造函数需要一个 name
    public Animal(string name)
    {
        Name = name;
        Console.WriteLine($"Animal 构造函数：{name}");
    }
}

class Dog : Animal
{
    public string Breed { get; set; }

    // 子类构造函数必须"喂饱"父类 —— 用 : base(...) 调用父类构造函数
    public Dog(string name, string breed) : base(name)
    {
        Breed = breed;
        Console.WriteLine($"Dog 构造函数：{breed}");
    }
}
```

```csharp
var dog = new Dog("旺财", "柴犬");
```

**执行顺序（这个必须记住）**：

```
1. 先执行父类 Animal 的构造函数   → 输出 "Animal 构造函数：旺财"
2. 再执行子类 Dog 的构造函数      → 输出 "Dog 构造函数：柴犬"
```

> **⚠️ 如果父类没有无参构造函数，子类就【必须】用 `: base(...)` 显式调用**，否则编译错误。
> 这和第 05 课的 `: this(...)` 是同一个语法，`base` 指父类，`this` 指本类。

### 调用父类的方法

```csharp
class Animal
{
    public virtual void Describe()
    {
        Console.WriteLine($"我是 {Name}");
    }
}

class Dog : Animal
{
    public override void Describe()
    {
        base.Describe();                    // ★ 先调用父类的版本
        Console.WriteLine("我还会汪汪叫");    // 再加上自己的
    }
}
```

> **Python 对照**：C# 的 `base.Xxx()` = Python 的 `super().xxx()`。

## 三、`virtual` 和 `override` —— 方法重写

### 问题：父类的方法不够用

```csharp
class Animal
{
    public void Speak() => Console.WriteLine("动物发出声音");
}

class Dog : Animal
{
    public void Speak() => Console.WriteLine("汪汪");     // ⚠️ 这其实是"隐藏"，不是重写
}
```

**C# 默认不允许"悄悄覆盖"父类方法**，因为那太危险了。想重写必须**两边都表明态度**：

```csharp
class Animal
{
    public virtual void Speak()                 // ① 父类：virtual 表示"这个方法允许被重写"
    {
        Console.WriteLine("动物发出声音");
    }
}

class Dog : Animal
{
    public override void Speak()                // ② 子类：override 表示"我要重写它"
    {
        Console.WriteLine("汪汪");
    }
}
```

### `virtual` / `override` / `new` 三者对比

| 父类怎么写 | 子类怎么写 | 效果 |
|---|---|---|
| `public virtual void F()` | `public override void F()` | ✅ **真重写**（多态生效） |
| `public void F()` | `public new void F()` | ⚠️ 隐藏父类方法（多态**不**生效） |
| `public void F()` | `public void F()` | ❌ 编译警告（应该用 `new` 或 `override`） |

**为什么一定要区分？** 因为**只有 `override` 才能享受多态**（下面第四节会看到区别）。

> **Python 对照**：
> Python 里直接定义同名方法就是重写，**不需要任何关键字**。
> C# 强制要求 `virtual` + `override`，好处是**"这个类的方法能不能被改"是明确的**。
> 你可以理解为：C# 把 Python 的"默认可变"改成了"默认不可变，想变要显式声明"。

## 四、★ 多态 —— 本课最重要的概念

### 先看一个"不神奇"的例子

```csharp
Dog dog = new Dog();
dog.Speak();              // 汪汪

Cat cat = new Cat();
cat.Speak();              // 喵喵
```

这没什么稀奇。**多态的威力在这里：**

```csharp
Animal a1 = new Dog();    // ★ 父类类型的变量，装子类对象
Animal a2 = new Cat();

a1.Speak();               // 汪汪 —— 实际调用的是 Dog 的版本！
a2.Speak();               // 喵喵
```

**同一句 `a1.Speak()`，执行哪个版本取决于"实际是什么对象"，而不是"变量声明成什么类型"。**

### 为什么这很强大

```csharp
// 不用多态：要为每种动物写一个方法
void MakeDogSpeak(Dog d) => d.Speak();
void MakeCatSpeak(Cat c) => c.Speak();
void MakeBirdSpeak(Bird b) => b.Speak();
// 加一种动物就要加一个方法…

// 用多态：一个方法搞定所有动物，将来加多少种都不用改
void MakeItSpeak(Animal a) => a.Speak();

Animal[] zoo = { new Dog(), new Cat(), new Bird() };
foreach (Animal a in zoo)
{
    a.Speak();            // 各自调用自己的版本
}
```

### 多态生效的前提

```csharp
class Animal
{
    public virtual void Speak() { }      // ← 必须 virtual
}
class Dog : Animal
{
    public override void Speak() { }     // ← 必须 override
}
```

**如果父类没写 `virtual`，或者子类用了 `new`，多态就不生效。**

### 一句话总结

> **多态 = 用父类的类型，调用子类的方法。**
> 让你能写"针对所有子类都通用"的代码，而不用关心具体是哪一种。

## 五、`abstract` 抽象类 —— 强制子类实现

**问题**：`Animal.Speak()` 里写什么？"动物发出声音"是废话——**每种动物的叫声都不同，父类根本不知道该怎么实现。**

```csharp
abstract class Animal                       // ① 类加 abstract
{
    public string Name { get; set; } = "";

    public abstract void Speak();           // ② 方法加 abstract，【没有方法体】
}
```

**`abstract` 的两条规则**：

| 规则 | 说明 |
|---|---|
| 抽象方法**没有方法体** | 只写签名，以分号结尾 |
| **抽象类不能 `new`** | `new Animal()` ❌ 编译错误 |

**子类必须实现所有抽象方法**：

```csharp
class Dog : Animal
{
    public override void Speak()            // 必须实现，否则编译错误
    {
        Console.WriteLine($"{Name}：汪汪");
    }
}
```

### 抽象类可以有"已实现"的方法

```csharp
abstract class Shape
{
    public abstract double GetArea();        // 抽象：子类必须实现

    public void Describe()                   // 已实现：子类直接继承
    {
        Console.WriteLine($"面积是 {GetArea():F2}");   // ★ 可以调用抽象方法！
    }
}
```

**注意 `Describe` 里调用了 `GetArea()`** —— 虽然 `Shape` 不知道面积怎么算，
但它知道"子类一定实现了 `GetArea`"。**这就是抽象类和多态配合的威力。**

## 六、`interface` 接口 —— "能做什么"

### 抽象类 vs 接口：先看区别

| | 抽象类 `abstract class` | 接口 `interface` |
|---|---|---|
| 表达的关系 | **"是一个"**（is-a） | **"能做什么"**（can-do） |
| 能继承几个 | **只能 1 个** | **可以多个** |
| 能有字段吗 | ✅ 能 | ❌ 不能 |
| 能有构造函数吗 | ✅ 能 | ❌ 不能 |
| 能有已实现的方法吗 | ✅ 能 | ✅ 能（C# 8+ 默认实现，但少用） |
| 命名惯例 | 普通名字 | **`I` 开头**（`IFlyable`） |

### 接口的定义和使用

```csharp
interface IFlyable                              // 惯例：I 开头
{
    void Fly();                                 // 接口成员默认就是 public abstract
    int MaxAltitude { get; }                    // 属性也可以
}
```

```csharp
class Bird : Animal, IFlyable                   // ★ 一个类只能继承一个父类，但能实现多个接口
{
    public override void Speak() => Console.WriteLine($"{Name}：啾啾");

    public void Fly() => Console.WriteLine($"{Name} 在飞");

    public int MaxAltitude => 1000;
}
```

**关键点**：
- `class Bird : Animal, IFlyable` —— **`Animal` 是父类（只能一个），`IFlyable` 是接口（可以有多个）**
- 实现接口的方法**必须写 `public`**（接口成员是 public 的）
- 实现接口的方法**不写 `override`**（因为不是重写，是"实现"）

### 为什么接口有用：一个方法处理所有"能飞的"

```csharp
void MakeItFly(IFlyable thing) => thing.Fly();

// 鸟能飞
MakeItFly(new Bird());
// 飞机也能飞（虽然它不是动物）
MakeItFly(new Airplane());
// 超人也能飞
MakeItFly(new Superman());
```

**接口把"能做什么"和"是什么"解耦了** —— `Airplane` 和 `Bird` 没有任何继承关系，
但它们都能 `Fly()`，所以都能传给 `MakeItFly`。

> **Python 对照**：
> Python 用**鸭子类型**——"能 `fly()` 就当它能飞"，不检查类型。
> C# 的接口是**显式契约**——必须明确声明 `: IFlyable` 才能传进去。
> **C# 更啰嗦，但编译器能帮你检查"这个对象真的能飞吗"。**

### 什么时候用抽象类，什么时候用接口？

| 场景 | 选择 |
|---|---|
| 多个类共享**实现代码**（字段、已实现的方法） | **抽象类** |
| 只定义**一组能力**，不关心实现细节 | **接口** |
| 需要**多继承** | **接口** |
| 表达"是一种" | 抽象类 |
| 表达"能做某事" | 接口 |

> **实用原则**：**优先用接口**（更灵活），只在"确实要共享实现代码"时才用抽象类。

## 七、`sealed` —— 禁止继承

```csharp
sealed class FinalClass                 // 这个类不能被继承
{
}

// class TryIt : FinalClass { }         // ❌ 编译错误
```

也用于**禁止重写某个方法**：

```csharp
class Base
{
    public virtual void F() { }
}

class Derived : Base
{
    public sealed override void F() { }   // 重写了，但之后的子类不能再重写
}
```

**什么时候用？** 当你不希望别人改动这个类的行为时（安全考虑或性能优化）。

## 八、类型判断和转换：`is` / `as`

有了继承，就经常需要判断"这个 `Animal` 到底是狗还是猫"：

### `is` —— 判断类型

```csharp
Animal a = new Dog();

if (a is Dog)                          // 判断是不是 Dog
{
    Console.WriteLine("这是一只狗");
}
```

### 模式匹配（推荐写法）

```csharp
if (a is Dog d)                        // ★ 判断 + 转换 + 声明变量，一步完成
{
    d.Bark();                          // 现在可以当 Dog 用了
}
```

### `as` —— 安全转换（失败返回 null）

```csharp
Dog? d1 = a as Dog;                    // 成功就拿到对象，失败给 null
if (d1 != null) d1.Bark();

// 对比强制转换：失败会抛异常
// Dog d2 = (Dog)a;                    // 如果 a 其实是 Cat，这里会崩
```

| 方式 | 失败时 | 什么时候用 |
|---|---|---|
| `is Dog` | 返回 false | 只判断 |
| `is Dog d` | 返回 false，`d` 未定义 | **判断+使用（推荐）** |
| `as Dog` | 返回 `null` | 不确定类型，想安全拿 |
| `(Dog)a` | **抛异常** | 你确定类型，想快速失败 |

## 九、本课新语法速查表

| 语法 | 作用 | Python 对照 | 易错点 |
|---|---|---|---|
| `class Dog : Animal` | 继承 | `class Dog(Animal):` | 只能一个父类 |
| `public Dog(...) : base(...)` | 调父类构造函数 | `super().__init__(...)` | 顺序：父类先执行 |
| `base.Method()` | 调父类方法 | `super().method()` | — |
| `virtual` | 允许被子类重写 | 无（Python 默认都可重写） | 忘了写 → 多态不生效 |
| `override` | 重写父类方法 | 无关键字 | 必须父类有 `virtual` |
| `new`（方法） | 隐藏父类方法 | 无 | **多态不生效** |
| **多态** | 父类变量装子类对象 | 同 | 前提是 `virtual`+`override` |
| `abstract class` | 抽象类，不能 new | `ABC` | 子类必须实现所有抽象方法 |
| `abstract void F();` | 抽象方法（无方法体） | `@abstractmethod` | 以分号结尾 |
| `interface IX` | 接口（I 开头） | `Protocol` | 成员默认 public |
| `class A : B, IX` | 继承 + 实现接口 | `class A(B, IX):` | 父类在前，接口在后 |
| `sealed` | 禁止继承/重写 | — | — |
| `a is Dog d` | 类型判断+转换（推荐） | `isinstance(a, Dog)` | — |
| `a as Dog` | 安全转换（失败 null） | — | — |
