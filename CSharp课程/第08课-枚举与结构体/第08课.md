## 一、为什么需要枚举

**问题**：用数字表示状态，代码没法读。

```csharp
int orderStatus = 2;              // 2 是什么意思？没人知道

if (orderStatus == 2)             // 2 是什么状态？
{
    // 魔法数字，看不懂，还容易记错
}
```

**用常量稍微好一点，但还是散落**：

```csharp
const int StatusPending = 0;
const int StatusShipped = 1;
const int StatusDelivered = 2;
```

**用枚举最干净**：

```csharp
enum OrderStatus
{
    Pending,        // 待处理
    Shipped,        // 已发货
    Delivered,      // 已送达
    Cancelled       // 已取消
}

OrderStatus status = OrderStatus.Shipped;

if (status == OrderStatus.Shipped)      // ★ 一眼看懂
{
    Console.WriteLine("订单已发货");
}
```

**好处**：
1. **可读** —— `OrderStatus.Shipped` 比 `2` 清楚一万倍
2. **编译器检查** —— 写错名字直接编译错误；赋值别的枚举类型也报错
3. **IDE 能补全** —— 打 `OrderStatus.` 会列出所有选项

> **Python 对照**：Python 用 `enum.Enum` 实现类似功能，但要手写更多代码。
> C# 的 `enum` 是**语言内置**的，用起来更简单。

## 二、枚举的底层是整数

**枚举成员默认从 0 开始，依次递增**：

```csharp
enum OrderStatus
{
    Pending,        // = 0
    Shipped,        // = 1
    Delivered,      // = 2
    Cancelled       // = 3
}
```

**可以验证**：

```csharp
Console.WriteLine((int)OrderStatus.Pending);      // 0
Console.WriteLine(OrderStatus.Shipped);           // Shipped
```

**可以显式指定值**：

```csharp
enum HttpStatus
{
    OK = 200,
    NotFound = 404,
    ServerError = 500
}

Console.WriteLine((int)HttpStatus.NotFound);      // 404
```

**数字和枚举可以互相转换**（需要显式转换）：

```csharp
OrderStatus s1 = OrderStatus.Shipped;
int n = (int)s1;                       // 枚举 → 数字（显式）
OrderStatus s2 = (OrderStatus)2;       // 数字 → 枚举（显式）

Console.WriteLine(s1);                 // Shipped
Console.WriteLine(n);                  // 1
Console.WriteLine(s2);                 // Delivered
```

> ⚠️ **注意**：`(OrderStatus)999` 也**能**通过编译，即使 999 不是任何枚举成员。
> 所以**不要用没定义的数字转枚举**，那会得到无效值。

**处理用户输入时，用 `Enum.TryParse`**（和第 01 课的 `TryParse` 一个套路）：

```csharp
if (Enum.TryParse<OrderStatus>("Shipped", out var parsed))
{
    Console.WriteLine($"解析成功：{parsed}");
}
else
{
    Console.WriteLine("无效的状态名");
}
```

**遍历所有枚举值**：

```csharp
foreach (OrderStatus s in Enum.GetValues<OrderStatus>())
{
    Console.WriteLine($"{s} = {(int)s}");
}
```

## 三、枚举的典型用法

### 用 `switch` 表达式处理枚举（最常用）

```csharp
OrderStatus status = OrderStatus.Shipped;

string description = status switch
{
    OrderStatus.Pending   => "等待处理中",
    OrderStatus.Shipped   => "已经发货，正在路上",
    OrderStatus.Delivered => "已送达",
    OrderStatus.Cancelled => "已取消",
    _                     => "未知状态"          // ← 兜底（虽然枚举理论上不会出现其他值）
};
Console.WriteLine(description);
```

> **⭐ 这里有个额外好处**：如果你给枚举**加了一个新成员**（比如 `Refunded`），
> 编译器会提醒你"这个 `switch` 可能没覆盖所有情况"——比用数字安全得多。

### 作为方法的参数和返回值

```csharp
static bool IsFinal(OrderStatus status) => status is OrderStatus.Delivered or OrderStatus.Cancelled;

static OrderStatus GetNextStatus(OrderStatus current) => current switch
{
    OrderStatus.Pending   => OrderStatus.Shipped,
    OrderStatus.Shipped   => OrderStatus.Delivered,
    _                     => current
};
```

## 四、`[Flags]` 位标志枚举 —— 表示"多个状态的组合"

**需求**：一个文件的权限可以**同时**是"可读 + 可写"，但不是"可执行"。

**普通枚举做不到组合**（一个变量只能是一个值）。用 `[Flags]` 可以：

```csharp
[Flags]                                  // ★ 加这个特性
enum FilePermission
{
    None      = 0,                       // 0000
    Read      = 1,                       // 0001
    Write     = 2,                       // 0010
    Execute   = 4,                       // 0100
    All       = Read | Write | Execute   // 0111
}
```

**⚠️ 关键点：值必须是 2 的幂**（1, 2, 4, 8, 16...），这样才能用二进制位表示不同状态。

**用法**：

```csharp
FilePermission p = FilePermission.Read | FilePermission.Write;   // 用 | 组合
Console.WriteLine(p);                       // Read, Write

// 检查是否包含某个权限（用 HasFlag 或 &）
if (p.HasFlag(FilePermission.Read))
{
    Console.WriteLine("有读权限");
}

// 添加权限
p |= FilePermission.Execute;                // 用 |= 添加

// 移除权限
p &= ~FilePermission.Write;                 // 用 &= ~ 移除
Console.WriteLine(p);                       // Read, Execute
```

**底层的位运算**：

```
Read    = 001
Write   = 010
Read|Write = 011      ← 组合就是"按位或"

检查 Read 是否存在： 011 & 001 = 001（非 0）→ 存在
```

> **Python 对照**：Python 用 `enum.IntFlag`，概念一样。
> `[Flags]` 在 .NET 里非常常见，比如 `FileAccess.ReadWrite`、`RegexOptions.IgnoreCase`。

## 五、`struct` 结构体 —— 值类型

**回顾第 01 课**：C# 有两大类类型

| | 值类型 | 引用类型 |
|---|---|---|
| 例子 | `int`、`double`、`bool`、`struct` | `class`、`string`、数组、`interface` |
| 赋值 `b = a` | **复制数据** | 复制地址 |
| 默认值 | 各字段为 0 / false | `null` |
| 住在哪 | 栈（局部变量时） | 堆 |

**`struct` 就是"你自己定义的值类型"**：

```csharp
struct Point                          // 用 struct 而不是 class
{
    public int X;
    public int Y;

    public Point(int x, int y)        // struct 也可以有构造函数
    {
        X = x;
        Y = y;
    }

    public override string ToString() => $"({X}, {Y})";
}
```

### 行为对比：struct vs class

```csharp
// struct：赋值是复制
Point p1 = new Point(1, 2);
Point p2 = p1;                        // ★ 复制整个数据
p2.X = 99;
Console.WriteLine(p1);                // (1, 2)  ← p1 没变

// class：赋值是复制地址
// （第 01/05 课已经验证过了）
```

### struct 的五条限制

| 限制 | 说明 |
|---|---|
| **不能继承** | `struct` 不能继承别的类，也不能被继承 |
| **不能有无参构造函数** | `struct` 永远有一个隐式的无参构造函数（把所有字段置零） |
| **不能有终结器** | `~StructName()` 不行 |
| **字段必须在构造函数里全部赋值** | 否则编译错误 |
| **默认不能为 null** | 除非用 `Point?`（`Nullable<Point>`） |

```csharp
struct Bad
{
    public int X;
    public int Y;

    public Bad(int x)         // ❌ 编译错误：没有给 Y 赋值
    {
        X = x;
    }
}
```

**从 C# 10 开始**，可以用 `record struct` 和字段初始化器简化写法（本课后面讲）。

## 六、⭐ 什么时候用 struct，什么时候用 class

**这是本课最重要的一节。** 用错了会带来性能问题或诡异的 bug。

### 微软官方的四条标准（全部满足才考虑 struct）

| # | 标准 | 说明 |
|---|---|---|
| 1 | **逻辑上表示单个值** | 像一个数字、一个坐标、一个金额 |
| 2 | **实例大小 < 16 字节** | 超过 16 字节，复制的成本就超过收益了 |
| 3 | **不可变**（immutable） | 创建后不该被修改 |
| 4 | **不会被频繁装箱** | 别把它存进 `object` 或非泛型集合 |

### 实用判断表

| 场景 | 用哪个 | 为什么 |
|---|---|---|
| 坐标 `(x, y)` | **`struct`** | 小、短命、像个数值 |
| 颜色 `(r, g, b, a)` | **`struct`** | 同样是"一组数值" |
| 复数、分数 | **`struct`** | 数学意义上的值 |
| 日期范围、金额 | 视情况 | 如果字段多，用 class |
| 学生、订单、用户 | **`class`** | 有身份、会变化、字段多 |
| 需要继承 | **`class`** | struct 不能继承 |
| 需要表示"没有"（null） | **`class`** 或 `struct?` | — |
| 字段加起来超过 16 字节 | **`class`** | 复制成本太高 |

### ⚠️ 踩坑示范：可变 struct 的经典陷阱

```csharp
struct Counter
{
    public int Value;
    public void Increment() => Value++;
}

var list = new List<Counter> { new Counter() };
// list[0].Increment();          // ❌ 编译错误！
//   因为 list[0] 返回的是【副本】，改副本没意义

// 正确做法：取出 → 改 → 放回
var c = list[0];
c.Increment();
list[0] = c;
```

**这就是"struct 应该不可变"的实际原因** —— 可变的 struct 到处是这种坑。

## 七、`readonly struct` 和 `record struct`

### `readonly struct` —— 一次性声明不可变

```csharp
readonly struct Point              // ★ 加 readonly
{
    public int X { get; }          // 只能是 get，不能 set
    public int Y { get; }

    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}
```

**好处**：编译器保证所有字段都是只读的，从根上避免"可变 struct"的坑。

### `record struct` —— 一行搞定的值类型数据

```csharp
record struct Point(int X, int Y);         // 和 record 一样简洁，但是值类型
readonly record struct Point3D(int X, int Y, int Z);   // 更常用：不可变的值类型
```

| 写法 | 类型 | 可继承 | 按值比较 |
|---|---|---|---|
| `class X` | 引用 | ✅ | ❌（除非重写） |
| `record X` | 引用 | ✅ | ✅ |
| `struct X` | 值 | ❌ | ✅（但慢，靠反射） |
| `record struct X` | 值 | ❌ | ✅ |

> **实用建议**：
> - 要"引用语义 + 按值比较" → `record`
> - 要"值语义 + 按值比较 + 小数据" → `readonly record struct`
> - 其他 → `class`

## 八、枚举和结构体组合实战

**这是现实中最常见的用法**：用枚举表示类型，用结构体表示一个"值对象"。

```csharp
enum Currency { CNY, USD, EUR }

readonly record struct Money(decimal Amount, Currency Currency)
{
    public override string ToString() => Currency switch
    {
        Currency.CNY => $"¥{Amount:F2}",
        Currency.USD => $"${Amount:F2}",
        Currency.EUR => $"€{Amount:F2}",
        _            => $"{Amount:F2} {Currency}"
    };
}

// 使用
var price = new Money(199.9m, Currency.CNY);
Console.WriteLine(price);                    // ¥199.90
```

**为什么这样设计好？**
- `Money` 是**不可变**的（record struct），不会被意外改动
- 按**值比较**：`new Money(10, CNY) == new Money(10, CNY)` 是 `true`
- **不会为 null**（值类型），少一类 bug
- 比用 `decimal` + `string` 两个变量清晰得多

## 九、本课新语法速查表

| 语法 | 作用 | Python 对照 | 易错点 |
|---|---|---|---|
| `enum Color { Red, Green }` | 定义枚举 | `class Color(Enum)` | 底层值从 0 开始 |
| `Color.Red` | 使用枚举成员 | `Color.Red` | — |
| `(int)Color.Red` | 枚举 → 整数 | `Color.Red.value` | 需要显式转换 |
| `(Color)1` | 整数 → 枚举 | `Color(1)` | **不做有效性检查** |
| `Enum.TryParse<T>(s, out v)` | 字符串 → 枚举 | — | 和 `int.TryParse` 一个套路 |
| `Enum.GetValues<T>()` | 遍历所有枚举值 | `for c in Color` | — |
| `[Flags]` | 位标志枚举 | `enum.IntFlag` | **值必须是 2 的幂** |
| `A \| B` / `HasFlag()` | 组合 / 检查标志 | `A \| B` | — |
| `struct Point { }` | 定义值类型 | `@dataclass(frozen=True)` 有点像 | **不能继承** |
| `readonly struct` | 不可变值类型 | — | 推荐写法 |
| `record struct P(int X, int Y);` | 一行值类型数据 | `@dataclass(frozen=True)` | — |
